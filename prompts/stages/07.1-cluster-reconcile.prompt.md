The iteration contract and the disposition mechanics for Stage 7.1 — the
per-cluster gate that closes cross-RDR drift before any member is implemented.
Run this alongside the stage's own paste block (`stages/07.1-cluster-reconcile.md`),
which builds the cluster (its step 1) and runs the set-scoped checks (its step 3).
The ITERATION CONTRACT below scopes those checks, so bind it first; the
DISPOSITIONS below are forced onto every finding those checks return.

Bind for this session:
  - {RDR_RECORDS} = the cluster's RDR directory.
  - {RDR_RESOURCES} / {RDR_ENV} = the seam files. Bind them with
    `eval "$("$RDR_HOME/bin/rdr" env)"` → `$RDR_ENV` / `$RDR_RESOURCES`. It
    applies nearest-wins (a repo-local `.rdr/workspace` beats the shared
    `$WS/.rdr-workspace`), so **never** source `$WS/.rdr-workspace` directly —
    under a repo-local marker that binds another project's seam. Keep it in the
    same shell as any command reading `$RDR_ENV`/`$EVIDENCE_DIR` (state dies
    between calls — re-run, don't carry). {RDR_RESOURCES} holds the
    corpora/design docs.
  - {EVIDENCE_DIR} = the cluster output dir {RDR_ENV} defines
    (`cluster-reconcile/<cluster>/` under that base): one `pairwise-<A>-<B>.md`
    per pair, a `critique-set.md` for the whole-set critique, and a
    `reconcile-report.md` per gate iteration (under an `iter-N/` subdir when the
    gate re-runs).
  - {ARTIFACT_DIR} = the per-member implementation-artifact dir {RDR_ENV} defines
    (its `status.md` is the unimplemented check below).

BUILD THE CLUSTER. The membership rule is a query — do not derive it by reading
candidates. One call:

  "$RDR_HOME/bin/rdr" index --json --cluster-of <NNNN> --closure --final-unimplemented

`cluster[]` is the set: each entry carries `record`, `title`, `status`,
`relation` — why it is in (`seed`, `declared` from `- **Cluster**:`,
`mutual-predecessor`, `peer-evidence`, `cross-cutting`) — `via` (the member
whose hop found it) and `impl_state` when a capsule exists. `out_of_scope[]`
is the record of what was dropped and why: `not-final`, `impl-complete`, or
`candidate` (the `mutual-mentions` tier — a LEAD, confirmed by re-running with
it added to the seeds, `--cluster-of A,B`, or dismissed; never expanded). A
member with no capsule stays in scope: nothing looked is not implemented.

DEPENDENCY SHAPES THAT DEADLOCK come first — one call over the corpus:

  "$RDR_HOME/bin/rdr" index --cycles --json

`findings[]`: `ownership-cycle` (predecessor/overrides/moved-to that come back
around — two records each overriding the other name no authority; `lint
--locking` blocks on the pair as `ownership:mutual`), `home-cycle` (Joint-check
homes deferring to each other — nothing can rule until one is broken),
`home-ahead-of-lock` (a Final member whose home is a Draft — a ruling change
there strands the lock; the drift this gate watches), `open-at-lock` (a Final
member with an OPEN check — it locked with a shared decision unruled). A
member in a cycle is routed back before anything else is reconciled: name the
arc to break in the report, do not reconcile around it.

OPEN JOINT DECISIONS are a query too — one call over the corpus:

  "$RDR_HOME/bin/rdr" index --open-joint --json

`open[]` carries both places a record states one: `signal=="status"` (the
Status line in joint-decision form; `qualifier` is the open question as
written) and `signal=="joint-check"` (a body `Joint-check: … (home: OPEN)`
line; `id`, `line`, `targets`, `home`). Keep to members of this cluster. For a
status-form member, `inspect --json --filter edges <NNNN>` → `kind=="joint-decision-home"`
names the home in `to`. So "which members hold an open joint decision, and
against what home" opens no member body — and no grep, which once lost the
only OPEN line to `| head`.

Vocabulary the query does not carry: a **home** is the single normative
anchor a joint decision is hoisted to — an umbrella-decision record §-anchor or
a shared interface. It is an input this gate does not otherwise watch: not a
member, and no gate walks it. The members holding a tolerance against one home's
open question are its **siblings**.

DETECT THE ITERATION. Ask, don't count:
`eval "$("$RDR_HOME/bin/rdr" paths --cluster <key> --next-iter <NNNN>)"` → `$ITER`
is N, `$ITER_DIR` is where this run writes (loose = iter-1, `iter-N/` after),
`$PRIOR_DIR` is the last report's dir. `$ITER_NOTE` names a gap if the segments
are not contiguous — report it, don't renumber into it. Then the cap is a row,
not a count (`open.txt` = the prior report's open ledger entries, one id per
line, empty or absent at N=1):

    R="$RDR_HOME/bin/rdr"
    intrastate flow resolve --model "$RDR_HOME/models/rdr-loop.toml" --outcome cluster-cap \
      --plan-only --tag iter="$ITER_BUCKET" \
      --tag open=$([ -s "$PRIOR_DIR/open.txt" ] && echo some || echo none)

`next=run` runs the gate with the `why` as its scope; `stopped:cluster-flapping`
is the stop packet (§stop-packet, rdr-common) — append the open entries AND
**the decomposition question** (is this cluster cut correctly at all?) with the
accumulated evidence, since no disposition here can express "re-cut the set".
Cure: §strong-consult (rdr-common) over the open entries, then the author. An
**answered tolerance's scoped answer-vs-fences check survives the stop** — it is
the home's obligation landing, not another gate pass; so do written deferrals
(dispositioned, not open; their checks are Stage 8's when the cluster resumes).

Record revisions as a file, and the moved set is a diff (members and each
joint-decision home, since a home is an input this gate does not otherwise
watch):

    for m in <member and home NNNNs>; do
      printf '%s %s\n' "$m" "$(git -C "$RDR_RECORDS" log -1 --format=%h -- "$RDR_RECORDS"/$m-*.md)"
    done | sort > "$ITER_DIR/revisions.txt"
    LC_ALL=C comm -3 "$PRIOR_DIR/revisions.txt" "$ITER_DIR/revisions.txt"   # moved

On a delta-scoped run:
  - **Origin ledger (anti-plank).** Iteration 1's findings table is the ledger;
    write this pass's open entries to `$ITER_DIR/open.txt`. A finding tracing to
    no ledger entry is **net-new scope**: record it with its evidence, but on
    its own it demotes no member and blocks no implement.
  - **Delta-scope the scans.** Re-run a pairwise scan only where the moved set
    names ≥1 member of that pair; an unchanged pair CARRIES its prior verdict.
    Re-run the whole-set critique only if the moved set is non-empty. A prior
    report with no `revisions.txt` → re-run everything and write it now.
    **Exception — an answered tolerance is always in scope.** A moved home has
    answered something — diff it and route each answer to the siblings
    tolerating that question; each owes its scoped answer-vs-fences check even
    if its own text never moved. A CARRIED pair carries its DEFERRED rows
    forward unexamined — correct (nothing moved, so the deferral stands), and
    not re-found, so they cannot be double-deferred.

FORCE ONE DISPOSITION. For each cross-RDR finding, force ONE disposition.
Ownership decides between
SPEC-DEFECT and JOINT-DECISION: a defect internal to one RDR is a
SPEC-DEFECT; a contradiction over a shared decision neither RDR solely owns
is a JOINT-DECISION. Cost decides DEFER-TO-IMPLEMENTATION: a real finding a
mechanical check settles for free is not worth a re-lock walk.
  - NO CONFLICT — the apparent overlap is consistent; record and move on.
  - JOINT-DECISION — NOT a spec defect: the siblings contradict over a decision
    that is jointly theirs. MARK the conflict in the report, HOIST the joint
    decision to a single normative home — the consumer's umbrella-decision
    record (e.g. an RFD) §-anchor, or a shared interface declared in both RDRs
    — cite-don't-restate, and let the siblings PROCEED under recorded
    tolerance: each stays Final with the qualifier `Final [joint decision →
    <home §-anchor>: <the open question>]` (see TEMPLATE.md), no demotion, no
    re-walk. This is the gate-side landing of the propose-time joint-decision
    check's promise: the siblings proceed once the joint decision has a home.
    A tolerance is an OPEN OBLIGATION, not a closure — it asserts "this
    question is unanswered at this sibling", never "this sibling is coherent",
    so name the question, not just the home. **When the home answers, every
    sibling holding a tolerance against that question owes a scoped check of
    the answer against its own normative fences — before that sibling re-locks
    or implements, whichever comes first.** The owner is whoever moves the
    sibling next (this gate on a re-run, else Stage 7 re-lock or Stage 8
    implement). Two outcomes: consistent with the frozen text → clear the
    qualifier and record the clearing; contradicts fenced text → a SPEC-DEFECT
    on the ordinary path (the SPEC-DEFECT disposition below).
    HOME FORM — one paragraph per decision: the decision and the user-visible
    stake, with derivation and alternatives in this gate's evidence tree, never
    the home. An entry that will not fit a paragraph is a decision not yet
    made. Hoisting buys O(k) conformance against one authority instead of O(k²)
    pairwise reconciliation, but only while the home stays small — an oversized
    home is just another peer. A sibling RESTATING a homed decision's mechanism
    prose is itself a finding (cite-don't-restate, above), repaired to the
    citation.
    FACTS OF RECORD — one artifact of record per shared census/figure/
    enumeration, named at the home, cited by peers, restated by none. A peer
    figure disagreeing with it is a CITATION REPAIR: repair the citation — no
    demotion, no tolerance, no deviation entry. It outranks
    DEFER-TO-IMPLEMENTATION, which covers a shared figure only while no
    artifact of record exists.
  - SPEC-DEFECT — a real contradiction/gap that blocks or risks impl. Name the
    LESS FOUNDATIONAL RDR of the pair to change (the MORE foundational stays
    Final), and size the re-entry SCOPE to the defect (*Re-entry scope*, in the
    stage doc). Then route it back in ONE edit — without touching its design
    body. Run rdr-common §rdr-write, `--outcome demote` then `--outcome readme`
    — one `--outcome demote` resolve PER demoted record, never one resolve
    generalized into a bulk flip (the per-record guards are the point):
      a. The flip carries the scope qualifier — `re-verify <assumption IDs the
         defect touches> @<stage> — <one-line reason>` (exact grammar in
         TEMPLATE.md Status). Pass the defect's class (`--tag blocker_class=`:
         `approach` FULL-FLOW | `contract` or `contradiction` STAGE-SCOPED at 3
         | `assumption-gap` STAGE-SCOPED at 4 | `wording` RE-LOCK-ONLY, which
         writes `re-verify none`) and the row writes `@<stage>` — what
         `/rdr-status` routes on; the TARGET RE-ENTRY STAGE below is
         `emit.stage`. The named IDs — the same set the re-entry note
         carries — are the only assumptions whose lock-time `Verified` stamp
         the defect disturbs; the rest stay lock-audited. The flip is the
         gate's job: a status change, not a content edit, and what lifts the
         freeze. The qualifier rides on the live Status value, so Stage 3's
         history-scrub never touches it and the Stage 7 re-lock flip overwrites
         it — the *durable* re-entry signal Stage 4 reads even after the
         working note is collapsed. (Leaving it Final contradicts this report.)
      b. The `## Refinement Context (cluster re-entry — delete on re-lock)`
         note lands after `## References`, carrying the disposition inline —
         cluster + date, peer pair, defect (quote the offending lines), TARGET
         RE-ENTRY STAGE (2 approach / 3 refine / 4 re-resolve / fix + /rdr-finalize), RE-ENTRY SCOPE
         (RE-LOCK-ONLY / STAGE-SCOPED / FULL-FLOW + one-line justification),
         resolution direction, pointer to this report — so a fresh session
         resumes knowing exactly how far to re-walk, without re-reading it.
    The note lands after the flip, when the RDR is already a Draft (not an
    amend; Drafts carry working context), and Stage 7 confirms it is gone
    before re-lock. The content fix itself is the re-entry stage's job.
  - DEFER-TO-IMPLEMENTATION — NOT a spec defect: a real finding too cheap to
    demote for. Qualifies only when ALL THREE hold: (a) the offending text sits
    OUTSIDE every ```normative fence (unfenced prose, Illustrative Code,
    Metadata, a peer's status claim, narration), or is a figure/count no
    contract's pass condition reads AND that no artifact of record covers (one
    that does is a citation repair, above); (b) a mechanical check at
    implementation decides it — a grep, a compile, or a test the RDRs already
    specify — so it cannot be silently wrong; (c) no clause's meaning changes:
    staleness or bookkeeping, not a contested decision. Record the finding, its
    evidence, and that check in the report, then WRITE it as a pre-seeded entry
    in the affected RDR's `<art>/deviations.md` (Stage 8's taxonomy — the
    artifact its completion gate must read to close), carrying an existing
    Type (usually TEST-FIXTURE) and the named check, left OPEN for Stage 8 to
    discharge: running the check IS its disposition, and it closes on the
    result like any other entry — it escalates only if the check comes back
    contradicting a contract. The RDR STAYS FINAL — no flip, no re-entry note,
    no re-walk — and the deferral does not block RECONCILED.
    GUARDRAILS: fenced normative text NEVER defers, and neither
    does a contradiction between two clauses' MEANING, fenced or not — both are
    SPEC-DEFECT. A deferral CLOSES its ledger entry (it is dispositioned, so it
    cannot drive the cap), but it is logged in the report's findings table as
    `DEFERRED`, and that log is what the next iteration diffs — write the
    deferred ids to `$ITER_DIR/deferred.txt`; a finding in
    `LC_ALL=C comm -12 <(cat "$EVIDENCE_DIR"/deferred.txt "$EVIDENCE_DIR"/*/deferred.txt 2>/dev/null | LC_ALL=C sort -u) <(for m in <members>; do "$R" anchors --record "$m" "$ITER_DIR"/*.md; done | LC_ALL=C sort -u)`
    (any prior iteration's `DEFERRED` entry) is a SPEC-DEFECT, not a second
    deferral.
