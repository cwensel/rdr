# Stage 8 — Finalize (Lock)

**Goal**: confirm nothing regressed, run the Finalization Gate, and flip Status
→ **Final**. After this the RDR is immutable — the implementation prompt treats
it as a contract.

## Paste this — first the readiness check

Fill `{RDR_PATH}` and `{RDR_ENV}` (default `_rdr/rdr-env.md`). The RDR
README/TEMPLATE (the gate lives in the template) are beside the flow docs.
Paste the **lock** prompt (below) only after you approve readiness.

```text
Review the RDR at {RDR_PATH}. Verify it against the rdr README and TEMPLATE
and identify exactly what's required to flip it to Final.

Read {RDR_ENV} for the pre-lock output location ({FLOW_DIR}). If reading those
outputs is heavy, delegate to a sub-agent that returns per-round "findings
closed? y/n + residue", not the raw round files.

FIRST run the mechanical sweep — the Tooling pass: open
../prompts/gate/tooling-pass.md and run its checks verbatim. It runs on every
RDR as a post-mutation regression check, since the rounds and the Stage 7
reconcile just rewrote this draft. If the sweep returns BLOCK, the RDR is NOT
READY — fix the regressions before the written responses below.

ALSO confirm no cluster re-entry note survives: a `## Refinement Context
(cluster re-entry — delete on re-lock)` block left by the 08.1 gate MUST be
gone by re-lock — its defect resolved and folded into live text. Stage 8 is the
one chokepoint every re-entry path (2/3/4) shares, so a surviving note is NOT
READY: the cross-RDR defect that demoted this RDR was never closed.

Then run the Finalization Gate from the template as written responses (not
checkboxes), each becoming part of the permanent record:
1. Contradiction Check — conflicts between Research Findings and Proposed
   Solution; planned features vs stated principles.
2. Assumption Verification — every Critical Assumption record internally
   consistent (Status/Method/Evidence agree, "If wrong" non-empty); no
   load-bearing Docs-Only without a Spike/Source-Search plan; no Source-Search
   self-reference.
3. Scope Verification — the Minimum Viable Validation is in scope, not
   deferred; name the specific test/proof.
4. Cross-Cutting Concerns — for each that applies, how this RDR addresses it
   or which peer RDR owns the policy. Omit (don't N/A-bullet) what doesn't.
5. Proportionality — right-sized; flag anything to trim before locking.

Report: READY (and what to change to lock) or NOT READY (with named
blockers). Do NOT flip status yet. Ultrathink only on a gate item genuinely
in doubt.
```

## Prompt — lock (only after you approve readiness)

```text
The gate is satisfied. Mark {RDR_PATH} as Final: set Status to Final, write
the gate's five responses into the Finalization Gate section, and update the
status/title row for this RDR in the RDR README index. Commit as a fixup to
the RDR's existing commit (we never amend RDRs as documentation — this is a
status flip with the gate record).
```

**Run when**: all analytical pre-lock rounds have run, findings resolved
(Stage 6), and Stage 7 returned RECONCILED (a small RDR arrives straight from
Stage 7). **Produces**: the mechanical-sweep verdict, the Finalization Gate's
written responses *in the RDR*, Status → Final, README index row updated.

## Review gate

- **Did the mechanical sweep run and PASS?** It runs on every RDR — including a
  small one that ran no Stage 5 round, where it is the *only* mechanical check.
  A C1 hollow-section or C2/C4 evidence finding is usually a regression a round
  or the reconcile introduced; a C3 self-reference is rare and means an
  evidence record was disturbed — treat it as a real blocker, not noise.
- **Is any cluster re-entry note gone?** A `## Refinement Context (cluster
  re-entry — delete on re-lock)` block surviving into Final means the 08.1
  defect was never closed. Stage 8 is its universal cleanup point, whichever
  stage (2/3/4) the RDR re-entered at.
- **Are the five gate responses *written*, not rubber-stamped?** A one-word
  "OK" defeats the purpose — each is a permanent statement.
- **Does the readiness check say READY**, no open blockers? A listed blocker
  names which earlier stage to return to (open spike / disturbed assumption →
  Stage 7; assumption gap → Stage 4; contradiction → Stage 3; scope/MVV gap →
  Stage 2). Assumption Verification should be near-trivial here *because*
  Stage 7 reconciled the open set — if it isn't, Stage 7 was skipped or
  incomplete.
- **Is the MVV genuinely in scope?** The most common false-lock is deferring
  the one end-to-end proof that the approach works.
- **Index updated?** The authoritative status lives in `../README.md`'s index,
  not just the RDR's Metadata.

If the readiness check says NOT READY, do **not** run the lock prompt. Return
to the stage the blocker names.

## Advance when

Status is Final, the gate's five written responses are in the RDR, and the
README index reflects it. This is exactly the entry contract
[Stage 9](09-implement.md) consumes — Status: Final, MVV in scope (Scope
Verification), predecessors COMPLETE — so lock and the launch prompt's
PRECHECKS meet at one stated contract.

→ Next: [09-implement.md](09-implement.md). Implementation is the flow's true
terminus; it usually begins hours or days after this lock, in a fresh session.
