# Stage 7 — Finalize (Lock)

**Goal**: confirm nothing regressed, run the Finalization Gate, and flip Status
→ **Final**. After this the RDR is immutable — the implementation prompt treats
it as a contract.

## Paste this

Fill `{RDR_PATH}`. Resolve `{RDR_ENV}` via the workspace marker (see README
*Where the seam lives* — `. "$WS/.rdr-workspace"` exports `$RDR_ENV`). The RDR
README/TEMPLATE (the gate lives in the template) are beside the flow docs.

This stage is **one gated prompt** —
[`../prompts/stages/07-finalize.prompt.md`](../prompts/stages/07-finalize.prompt.md).
It runs the mechanical sweep + the five written gate responses, then **the
verdict is the gate**: READY locks in the same pass (Status → Final, gate
responses written, README index updated, and — if autocommit is on — a standalone
`docs(rdr): finalize … (Gate PASS)` commit, never a `fixup!`); NOT READY flips nothing
and names the return stage. A single gate item genuinely in doubt stops per
§stop-packet rather than guessing the lock.

**Run when**: all analytical pre-lock rounds have run, findings resolved
(Stage 6), and Stage 6 returned RECONCILED (a small RDR arrives straight from
Stage 6). **Produces**: the mechanical-sweep verdict, the Finalization Gate's
written responses *in the RDR*, Status → Final, README index row updated.

## Review gate

- **Did the mechanical sweep run and PASS?** It runs on every RDR — including a
  small one that ran no Stage 5 round, where it is the *only* mechanical check.
  Read its verdict against the prompt file's own *Expected signal* section: a
  BLOCK is a real regression a round or the reconcile introduced (or a disturbed
  evidence record), not noise — fix it before locking.
- **Is any cluster re-entry note gone?** A `## Refinement Context (cluster
  re-entry — delete on re-lock)` block surviving into Final means the 07.1
  defect was never closed. Stage 7 is its universal cleanup point, whichever
  stage (2/3/4) the RDR re-entered at.
- **Are the five gate responses *written*, not rubber-stamped?** A one-word
  "OK" defeats the purpose — each is a permanent statement.
- **Did any conditional mini-check cue fire (fallback/derived · absence/no-op
  oracle · deparse/round-trip · drop/filter)?** If so, its compact table
  (`authority`/`oracle`/`fidelity`/`disposition`) is present in the RDR and the
  prelock close packet's RDR-delta named it. A fired cue with no table is NOT READY.
  This is a presence check, not a re-run of the mini-check.
- **Did the Determinacy trigger fire on a `mid`/`large` RDR?** If Normative
  Contracts name step-ordering, parse/deparse, import/export, compose/decompose,
  hashing, identity, migration, ambiguous field ownership, or multi-step MVV
  fidelity, `evidence/repeatability/run-1.md` + `diff.md` or a written
  `determinacy: n/a - <reason>` disposition must exist. Otherwise NOT READY.
- **Does the verdict say READY**, no open blockers? A listed blocker
  names which earlier stage to return to (open spike / disturbed assumption →
  Stage 6; assumption gap → Stage 4; contradiction → Stage 3; scope/MVV gap →
  Stage 2). Assumption Verification should be near-trivial here *because*
  Stage 6 reconciled the open set — if it isn't, Stage 6 was skipped or
  incomplete.
- **Is the MVV genuinely in scope?** The most common false-lock is deferring
  the one end-to-end proof that the approach works.
- **Index updated?** The authoritative status lives in `../README.md`'s index,
  not just the RDR's Metadata.

On NOT READY the prompt flips nothing — return to the stage the blocker names.

## Advance when

Status is Final, the gate's five written responses are in the RDR, and the
README index reflects it. This is exactly the entry contract
[Stage 8](08-implement.md) consumes — Status: Final, MVV in scope (Scope
Verification), predecessors COMPLETE — so lock and the launch prompt's
PRECHECKS meet at one stated contract.
