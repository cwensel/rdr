# Stage 7 — Finalize (Lock)

**Goal**: confirm nothing regressed, run the Finalization Gate, and flip Status
→ **Final**. After this the RDR is immutable — the implementation prompt treats
it as a contract.

## Paste this

Fill `{RDR_PATH}`. Resolve `{RDR_ENV}` via the workspace marker (see README
*Where the seam lives* — `. "$WS/.rdr-workspace"` exports `$RDR_ENV`). The RDR
README/TEMPLATE (the gate lives in the template) are beside the flow docs.

This stage is **one gated prompt** —
[`../prompts/stages/07-finalize.prompt.md`](../prompts/stages/07-finalize.prompt.md).
It runs the mechanical sweep + the five written gate responses, then **the
verdict is the gate**: READY locks in the same pass (Status → Final, gate
responses written to `{ARTIFACT_DIR}/gate.md` with the pointer line in the RDR,
README index updated, and — if autocommit is on — a standalone
`docs(rdr): finalize … (Gate PASS)` commit, never a `fixup!`); NOT READY flips nothing
and names the return stage. Mechanical sweep findings (hollow-but-fillable
sections, surviving template text — old-template blocks included, anchor
rewrites) are Stage 7's own in-pass fix, never routed to Refine; only
substantive findings (new evidence, a design call) return to the stage whose
contract covers them, and never twice for the same finding (loop-breaker →
§stop-packet). A single gate item genuinely in doubt stops per §stop-packet
rather than guessing the lock.

**Run when**: all analytical pre-lock rounds have run, findings resolved
(Stage 6), and Stage 6 returned RECONCILED (a small RDR arrives straight from
Stage 6). **Produces**: the mechanical-sweep verdict, the Finalization Gate's
written responses *in `{ARTIFACT_DIR}/gate.md`* (the RDR carries the pointer
line), Status → Final, README index row updated.

## Review gate

- **Did the mechanical sweep run and PASS?** It runs on every RDR — including a
  small one that ran no Stage 5 round, where it is the *only* mechanical check.
  Read its verdict against the prompt file's own *Expected signal* section: a
  BLOCK is a real regression a round or the reconcile introduced (or a disturbed
  evidence record), not noise. Mechanical findings the prompt fixes in-pass and
  re-sweeps; only substantive ones route back — and never twice for the same
  finding (loop-breaker → §stop-packet).
- **Is any cluster re-entry note gone?** A `## Refinement Context (cluster
  re-entry — delete on re-lock)` block surviving into Final means the 07.1
  defect was never closed. Stage 7 is its universal cleanup point, whichever
  stage (2/3/4) the RDR re-entered at.
- **Are the five gate responses *written* in `{ARTIFACT_DIR}/gate.md`, not
  rubber-stamped?** A one-word "OK" defeats the purpose — each is a permanent
  statement.
- **Did any conditional mini-check cue fire (fallback/derived · absence/no-op
  oracle · deparse/round-trip · drop/filter · multi-assertion surface/MVV)?**
  If so, its compact table
  (`authority`/`oracle`/`fidelity`/`disposition`/`trace`) is present in the RDR
  and the prelock close packet's RDR-delta named it. A fired cue with no table
  is NOT READY, as is a `trace` table retaining a CONTRADICTION row.
  This is a presence check, not a re-run of the mini-check.
- **Is repeatability-lite settled?** §lens-row's call with
  `--outcome repeatability` (follow a `resolve:determinacy` chain once) must
  emit `next = none`; anything else is NOT READY, class `determinacy`, with
  `emit.surface` quoted.
- **Is every joint-decision fire homed, and is the overlap set still clear?**
  The lock refuses a `Joint-check:` whose home is `OPEN`
  (`stopped:joint-decision-open`); a home the tool cannot resolve reads
  `unhomed` on the vector and locks, vouched for by the written response. The
  prompt's `--outcome fence` call re-runs propose's two query arms scoped to
  this record: `stopped:overlap-uncited` is NOT READY. Both are tool values —
  never read the line or the pairs by eye.
- **Does the verdict say READY**, no open blockers? A listed blocker
  carries its class, and rdr-common §rdr-write `--outcome return` names the
  stage it returns to. Assumption Verification should be near-trivial here *because*
  Stage 6 reconciled the open set — if it isn't, Stage 6 was skipped or
  incomplete.
- **Is the MVV genuinely in scope?** The most common false-lock is deferring
  the one end-to-end proof that the approach works.
- **Index updated?** The authoritative status lives in `../README.md`'s index,
  not just the RDR's Metadata.

On NOT READY the prompt flips nothing — return to the stage the blocker names.
